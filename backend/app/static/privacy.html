Privacy Policy

Effective Date: October 21, 2026 • Document Version: 1.0 (Draft for Governance Review)

1. Scope and Architecture Overview

TwinCore provides automated developer intelligence and deterministic software digital twins by indexing source repositories, building syntax symbol graphs, and modeling change impact. This Privacy Policy discloses the data TwinCore processes, where data resides, and how users can inspect or purge their data.

2. Information We Collect and Process

  • Account Information: Username, email address, password hash (salted and hashed via PBKDF2-HMAC-SHA256 or identity provider tokens), and role designations.
  • Session Credentials: Ephemeral session tokens or signed JWT credentials used strictly for stateless authentication.
  • Repository Metadata: Repository names, remote clone URLs, branch names, Git commit SHAs, author timestamps, and commit messages.
  • Structural Code Signatures: Abstract Syntax Tree (AST) symbol locations, class/function definitions, typed dependencies, and module relationship maps.
  • Diagnostic Telemetry: Anonymized HTTP request headers, correlation request IDs (X-Request-ID), and aggregated error summaries.

3. How Source Code is Handled

TwinCore analyzes source code to build a software digital twin graph:

  • Source files acquired during git cloning or archive uploads are analyzed locally within isolated directories.
  • Source code content is scanned for structure; raw code files are not retained permanently in public stores.
  • Secret scanning heuristics are executed to prevent recording private API tokens or credentials into evidence stores.
  • External AI Sharing: TwinCore relies primarily on deterministic local AST analysis. When external language model services are queried for natural language simulation explanations, queries are sanitized and do not transmit full private source code repositories without user authorization.

4. Data Storage and Retention

TwinCore stores structured digital twin records, snapshot relationships, and account entities in PostgreSQL/Supabase databases. Data is maintained for as long as your account remains active or until you delete specific repositories or your account.

5. User Control and Account Deletion

You maintain control over your repositories and personal data:

  • Repository Deletion: You can delete any repository you own at any time via the API or user interface. Deletion cascades to all associated snapshots, structural artifacts, typed relationships, and analysis runs.
  • Complete Account Deletion: You may permanently delete your account directly through your user profile settings (DELETE /api/v1/auth/account). This transactionally purges your user profile, active sessions, and all owned repositories.

6. Security Measures

TwinCore implements industry-standard technical and operational safeguards: authenticated session cookies with HttpOnly, SameSite, and Secure flags; multi-tenant row-level authorization; archive traversal protections; rate limiting on authentication and intensive analysis operations; and TLS transport encryption.

7. Contact and Inquiries

For privacy inquiries, governance questions, or data removal verification, please contact your TwinCore deployment administrator or engineering lead.
