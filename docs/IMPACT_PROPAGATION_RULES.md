## 1. Executive Summary

This document establishes the formal, deterministic specification for Change Impact Analysis in the Software Digital Twin.
Every change impact finding generated by the system must be governed by an explicit rule from this registry.
Informal or ad-hoc heuristic if/else statements are strictly prohibited.

---

## 2. Core Propagation Invariant: Explicit Directionality

In software dependency analysis, edge traversal direction is governed by dependency physics:

$$\text{Caller } B \xrightarrow{\text{CALLS}} \text{Callee } A$$

- When **Callee $A$** is modified, the change propagates **in reverse** ($\leftarrow$) to **Caller $B$**, because $B$ relies on the signature, contract, and behavioral invariance of $A$.
- When **Caller $B$** is modified, the change **does not** automatically propagate forward to Callee $A$.

### Directionality Classification:
- **`REVERSE` Traversal**: The change triggers on the `target` node of the edge, propagating backward to the `source` node. (Applicable to: `CALLS`, `IMPORTS`, `DEPENDS_ON`, `CONSUMES`, `EXTENDS`, `IMPLEMENTS`, `TESTS`, `PERSISTS_TO`).
- **`FORWARD` Traversal**: The change triggers on the `source` node of the edge, propagating forward to the `target` node. (Applicable to: `EXPOSES`, `PARTICIPATES_IN`, `TRANSITIONS_TO`).

## 4. Impact Classification Taxonomy

Impact must not be conflated with Risk or Confidence.
- **`DIRECT`**: Exactly distance 1 along an incoming typed relationship.
- **`PROVEN_TRANSITIVE`**: Distance $\ge 2$ along a chain of verified, typed AST relationships.
- **`MULTI_HOP`**: Canonical summary category for all transitive paths.
- **`LIKELY`**: Path relies on structural alias resolution (e.g. Vite `@/services` $\to$ `src.services`) or file-stem heuristic.
- **`POSSIBLE`**: Path crosses dynamic dispatch, unverified reflection, or external module boundaries.
- **`UNKNOWN`**: Incomplete graph coverage or unresolved imports. Epistemic uncertainty is preserved; never converted to unaffected.

---

## 5. Termination & Cycle Invariants

1. **Cycle Protection**: No traversal path may revisit any node already present in its current branch path stack (`if affected_id in path_ids: continue`).
2. **Depth Pruning**: If an entity has already been reached from the same root change at a shallower depth, deeper redundant traversals are pruned.
3. **Max Depth Bound**: Traversal terminates at `config.max_depth` (default: 5).
