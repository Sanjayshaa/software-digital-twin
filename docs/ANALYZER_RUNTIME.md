# Analyzer Runtime Architecture

## 1. Runtime Pipeline

The Analyzer Runtime consumes the `AnalysisPlan` generated by the Phase 2 Discovery Brain. It never executes arbitrary shell commands or code from the analyzed repository.

```
AnalysisPlanResult (from Phase 2 Discovery)
       ↓
AnalyzerDispatcher (maps plan steps to active registered analyzers)
       ↓
AnalyzerRunner (orchestrates execution with sandboxed file inventory)
       ↓
[PythonAnalyzer | JavaAnalyzer | TypeScriptAnalyzer | JavaScriptAnalyzer | SecondaryAnalyzers]
       ↓
ParserAdapter (Tree-sitter AST & Specialized Lexers)
       ↓
ExtractedArtifacts + ExtractedRelationships + ExtractedEvidence
       ↓
TwinPersistenceWriter (idempotent upsert into PostgreSQL)
```

## 2. Parser Adapter Boundary

To decouple the Digital Twin from specific AST implementations, all source-code parsing passes through `ParserAdapter`:
- `ParserAdapter.parse_source(source_bytes: bytes, file_path: str) -> ParserResult`
- `ParserResult`: decoupled container with `root_node: SyntaxNode`, `errors: List[str]`, `source_code: str`.
- `SyntaxNode`: tree node containing `node_type`, `text`, `start_line`, `start_col`, `end_line`, `end_col`, `children`.

### Tree-sitter Adapter (`TreeSitterAdapter`)
- Primary parsing layer for Python, Java, JavaScript, and TypeScript.
- Uses official language grammars (`tree_sitter_python`, `tree_sitter_java`, `tree_sitter_javascript`, `tree_sitter_typescript`).
- Reports syntax anomalies in `errors` while preserving partial parse trees so a single syntax error never aborts repository analysis.

## 3. Polyglot Language Analyzers

### Deep Analyzers (Level 3-4 Capability)
1. **Python Structural Analyzer (`PythonStructuralAnalyzer`)**:
   - Modules, imports (`import x`, `from x import y`), classes, inheritance, methods, functions.
   - Statically observable function calls (`CALLS`).
   - FastAPI route decorators (`@app.get`, `@app.post`) -> `API_ENDPOINT` + `EXPOSES`.
   - Pytest test cases (`def test_*`) -> `TEST_CASE` + `TESTS` target.

2. **Java Structural Analyzer (`JavaStructuralAnalyzer`)**:
   - Packages (`PACKAGE`), imports, classes, interfaces, superclasses (`EXTENDS`), methods, constructors.
   - Spring REST annotations (`@RestController`, `@GetMapping`, `@PostMapping`) -> `API_ENDPOINT` + `EXPOSES`.
   - JUnit test annotations (`@Test`) -> `TEST_CASE` + `TESTS` target.

3. **TypeScript & React Analyzer (`TypeScriptStructuralAnalyzer`)**:
   - Modules, imports, exports (`named_export`, `default_export`) -> `EXPORTS`.
   - Classes, methods, functions, React functional components.
   - Vitest / Jest test blocks (`describe`, `it`, `test`) -> `TEST_CASE` + `TESTS`.

4. **JavaScript / Node.js Analyzer (`JavaScriptStructuralAnalyzer`)**:
   - Reuses the Tree-sitter JS grammar for CommonJS (`require`, `module.exports`) and ES modules (`import`, `export`).

### Secondary Structural Analyzers (Level 1-2 Capability)
5. **COBOL Structural Analyzer (`CobolStructuralAnalyzer`)**:
   - Mainframe program modules, structural divisions (`IDENTIFICATION`, `ENVIRONMENT`, `DATA`, `PROCEDURE`).
   - `COPY` statements -> `COPY_DEPENDS_ON` relationships to copybooks.

6. **C / C++ Structural Analyzer (`CppStructuralAnalyzer`)**:
   - File units, `#include` directives -> `INCLUDES` relationships.
   - Structs (`CPP_STRUCT`), classes, methods, functions.

7. **Database DDL Analyzer (`DatabaseStructuralAnalyzer`)**:
   - SQL DDL scripts, `CREATE TABLE` -> `SQL_TABLE`, `CREATE VIEW` -> `SQL_VIEW`.

8. **Docker & Infrastructure Analyzer (`DockerStructuralAnalyzer`)**:
   - `Dockerfile` stages -> `DOCKER_STAGE`.
   - `docker-compose.yml` service blocks -> `DOCKER_STAGE`.
